# 写真の identity を不透明な ID にし、URL とファイル名をそこから導出する

写真は生成時に不透明な短い ID（`photoId`）を持ち、これを唯一の identity とする。S3 のキーは `gallery/{photoId}.webp` のようにフラットで、バリアント名も撮影日も含まない。派生物の URL も `photoId` から規約で組み立てる。sidecar のファイル名だけは `{capturedAt}-{photoId}.yaml` として人間が読める形にする。

従来は URL が実質的な identity であり、撮影日時はファイル名から正規表現で復元されていた。ID を不変にし、可変なデータ（撮影日は後から修正されうる）や集合の状態（連番は採番のために全体を読む必要がある）から切り離すことで、バリアントの改名・写真の付け替え・CDN ドメインの変更が、S3 のオブジェクトを一切動かさずに行える。

## 帰結

- URL はデータを見ただけでは分からず、URL 組み立て関数（`packages/gallery-schema`）を経由しないと得られない。
- S3 のバケットを人間が直接覗いたときの可読性は失われる。運用は gallery-manager 経由に限られる前提で受け入れる。
- ファイル名は人間のため、`photoId` は機械のためという役割分担になる。撮影日を修正するとファイル名は変わるが、URL は動かない。
