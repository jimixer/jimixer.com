# 原本を非公開バケットに保管し、その保存成功を公開の事前条件にする

撮影された原本は非公開の S3 バケット（Standard-IA）へ保管し、以後書き換えない。gallery-manager は**原本の保存が成功しない限り派生物を公開しない**。写真をサイトから降ろす操作は sidecar と派生物を削除するが、原本は削除しない。

ここでいう原本は「撮影された無加工のファイル」ではなく「公開用ファイルを生成した直接の元ファイル」である。加工を経ている写真では加工後のファイルが原本にあたる。加工は手作業であり機械的に再現できないため、生キャプチャを保管しても派生物を作り直せないことがある（実例: `kipfel-01`）。生キャプチャは保管の対象にしない。

従来は 2048px / quality 85 の WebP が原本を兼ねており、原本は保持されていなかった。これは「2026年3月時点の変換設定」を永久に固定するもので、フォーマットの移行・より大きなサイズ・サムネイルのクロップやり直しのすべてを不可能にする唯一の不可逆な損失だった。

保管先に Glacier Deep Archive を選ばないのは、想定用途が「数年後に全件を再処理する」ことであり、取り出しに最大12時間・最低保管期間180日という制約が用途と噛み合わないため。数GB 規模では Standard-IA との月額差が $0.1 未満で、最適化する意味がない。

## 帰結

- 原本の保存が失敗した写真は公開されない。失敗が沈黙して「原本の無い写真」が生まれることを防ぐ。
- 「サイトから降ろす」と「原本を捨てる」は別の操作になり、後者は gallery-manager から実行できない。
- CI で「原本の集合 ⊇ sidecar の集合」を検証する（原本の無い写真は存在してはいけない）。
